# Spec: Coverage Honesty & Type-Check Coverage

> Wave 11 — the gates that reported green while measuring less than they claimed.

## Problem

Three checks in this repo could pass while not verifying what they appeared to verify.
None of them were failing. All three were green.

### 1. Four components were invisible to the coverage thresholds

`vitest.config.ts` sets `coverage.include` to `src/**/*.ts` and `src/**/*.tsx`, and
`vitest.config.ts` excluded `src/components/ui/**`, `src/hooks/**`, `src/pages/**`,
`src/components/options/**` and `src/components/editor/components/**` — deliberately,
each with a written reason. But four components in `src/components/` itself were
**not** excluded and still never appeared in the report:

```
src/components/ConfirmDialog.tsx
src/components/ImportWizard.tsx
src/components/NewSnippetView.tsx
src/components/SnippetDetailView.tsx
```

The mechanism, confirmed end to end:

1. All four import `#i18n`, the WXT virtual module generated by `wxt prepare`.
   `vitest.config.ts` had no alias for it, so it was unresolvable.
2. Unresolvable `#i18n` means no unit test can load these files, so they never run —
   they become "untested files" as far as the coverage provider is concerned.
3. To report 0% for an untested file, `@vitest/coverage-v8` transforms it through
   its own pipeline. That pipeline cannot resolve `#i18n` either.
4. `getSources()` swallows the failure with `.catch(() => null)`, falls back to
   reading the **raw `.tsx` off disk**, and hands TypeScript to rollup's
   **JavaScript-only** parser.
5. That parser fails on the type annotations. The provider logs
   `Failed to parse … Excluding it from coverage.` and **exits 0**.

Measured: 124 source files → 50 after `coverage.exclude` → **46 in
`coverage-final.json`**. The 80/80/75/80 thresholds were computed over 46 files
while the config asked for 50.

### 2. The one `.tsx` that _was_ measured was at 28% and averaged away

```
components              |   29.41 |     7.69 |    16.66 |      28 |
  ...tListItem.tsx      |   29.41 |     7.69 |    16.66 |      28 | 69-167
```

`src/components/` contained exactly one measured file, at 28% lines and 7.7%
branches, and passed anyway. There was no per-directory floor. The global 91.76%
was carried by pure-logic modules (`dateUtils` 100%, `usageTracking` 97%).

### 3. The e2e suite was never type-checked

`tsconfig.e2e.json` existed and was referenced by **nothing** — not `package.json`,
not CI, not any doc. It covered `e2e/**/*.ts` + `playwright.config.ts`. The eight
errors that had accumulated there included two that were silently inert at runtime:

```ts
await expect(preview).toBeVisible({
  timeout: 5000,
  message: "preview should open when typing / after existing text", // ignored
});
```

Playwright 1.61's `toBeVisible` accepts only `timeout` and `visible`. JavaScript
ignores an unknown option, so those diagnostics were never shown to anyone. A
reviewer reading that test would have believed each assertion carried its own
failure message. It did not.

Separately, `tsconfig.node.json` — referenced from `tsconfig.json` — named
`vite.config.ts` and `manifest.ts`, neither of which exists. It reported
`TS18003: No inputs were found` and exited 0.

## Solution

### The `#i18n` alias — the actual fix

Alias `#i18n` to `tests/mocks/i18n.ts` in `vitest.config.ts`. The stub resolves
real keys against the real `src/locales/en.yml` and applies the real `$1`/`$2`
substitutions, so a test that renders a component sees the actual user-visible
English copy. A missing key returns the key itself, so a locale regression is
legible in a failure rather than rendering as an empty string.

This is not a string-concatenation fake (AGENTS.md rule 1). It is a lookup, so
assertions on rendered copy are meaningful, and it works without a per-test mock.

**Verified:** `#i18n` import correlates perfectly with the defect — all 4 dropped
files import it, and **zero** of the 46 kept files do.

### Coverage integrity gate

`scripts/check-coverage-integrity.mjs` reconstructs the intended file set from
`vitest.config.ts` itself (so it cannot drift as `coverage.exclude` changes) and
fails if the set differs from the keys in `coverage-final.json`. It errors rather
than skipping on a glob it cannot expand, because a silently unexpanded glob would
understate the intended set — the exact failure it exists to prevent.

### Thresholds corrected to the truth

The honest measurement over all 50 files is **81.76 / 73.94 / 76.58 / 81.76**.
The global thresholds are now `81 / 73 / 76 / 81`.

**These are lower than the 80/80/75/80 they replace, and that is a correction,
not a relaxation.** The old numbers described 46 files. The new ones describe all
50, including four at 0%. The suite now fails if coverage _regresses_.

Added per-directory floors, so a regression in any one directory fails loudly
instead of being averaged into the global number.

Vitest applies a glob threshold as an **aggregate over every file the glob
matches** — not per file, and not as the printed report row. The floors below
are the measured aggregates, floored to integers:

| Scope               | measured s/f/b        | floor lines | functions | branches |
| ------------------- | --------------------- | ----------- | --------- | -------- |
| global (ratchet)    | 81.76/73.94/76.58     | 81          | 73        | 76       |
| `src/components/**` | 3.48 / 1.79 / 0.75    | 3           | 1         | 0        |
| `src/lib/**`        | 91.24 / 90.00 / 86.62 | 91          | 90        | 86       |
| `src/storage/**`    | 98.51 / 97.67 / 93.88 | 98          | 97        | 93       |

An earlier revision set these from the printed report rows and put `lib` at 80
against a real 91.24, describing them as "honest current values". A floor eleven
points below the truth would not catch a meaningful regression in that directory.

### e2e type-checking wired in

`pnpm compile` is now `compile:src && compile:e2e`. All eight errors are fixed at
the source rather than suppressed:

- Two inert `message` options removed; the diagnosis moved into the comment above
  the assertion, where it is actually read.
- `Text | null` narrowing made explicit via a type predicate plus a thrown error,
  replacing a `worldText!` non-null assertion that hid the problem.
- `Page` imported from `@playwright/test`, which is where it is declared —
  `fixtures.ts` imports it but does not re-export it.
- `chrome` declared in `e2e/globals.d.ts`, limited to the surface the suite
  actually touches, for `page.evaluate` callbacks that execute in the browser.
- `tsconfig.node.json` repointed at the three root configs that exist
  (`wxt`, `vitest`, `playwright`).

## Acceptance Criteria

- [x] `scripts/check-coverage-integrity.mjs` **fails** when run against the
      pre-fix report, naming exactly the four affected files.
- [x] After the alias, it passes: all 50 configured files present.
- [x] `pnpm test:coverage` includes all four previously-missing components at 0%.
- [x] `pnpm compile` type-checks `e2e/**` and exits 0.
- [x] `tsconfig.node.json` resolves real inputs and exits 0.
- [x] Coverage thresholds fail on regression rather than passing on a reduced file set.

## Negative Cases

- [x] **A glob the script cannot expand is a hard error**, not a skip — verified
      by pointing it at `src/entrypoints/**`, which it rejected rather than
      silently dropping from the intended set.
- [x] **A file present in the report but not in the intended set also fails**, so
      the gate is not one-directional.

## Known Gaps

These are tracked, not hidden. They are the reason `src/components/**` has a floor
of 3 rather than 80.

- `ConfirmDialog.tsx`, `ImportWizard.tsx`, `NewSnippetView.tsx`,
  `SnippetDetailView.tsx` — 0%, now measured and visible.
- `SnippetListItem.tsx` — 28% lines / 7.7% branches despite having a test file.
- `src/lib/sentry-content.ts` — 0%.
- `src/lib/importers/types.ts` — 0% (type-only module; a runtime-coverage
  measurement of a file with no executable statements is not meaningful).
