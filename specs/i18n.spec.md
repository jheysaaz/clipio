# i18n — coverage and dead-key hygiene

## Problem

Two failures with the same root cause: **nothing checked whether a translated key was actually
used, and nothing checked whether user-visible text was actually translated.**

### 1. The options sidebar was hardcoded English

`src/components/options/app-sidebar.tsx` declared its navigation as literals:

```ts
const NAV_ITEMS: NavItem[] = [
  { id: "dashboard", label: "Dashboard", icon: LayoutDashboard },
  { id: "snippets", label: "Snippets", icon: FileText },
  …
```

Meanwhile `options.nav.dashboard`, `options.nav.snippets`, `options.nav.appearance`,
`options.nav.images` and `options.nav.advanced` existed in **both** `en.yml` and `es.yml`,
translated, and were read by nothing. A Spanish user saw an English sidebar beside a translated
page — and someone was maintaining five Spanish translations of strings the UI never displayed.

That pair of facts — translated keys, zero readers — is exactly what an unused-key check reports,
which is why the check below found the bug rather than the bug being found by inspection.

### 2. The locale gate was half a gate

`scripts/check-locales.mjs` verified that every key in `en.yml` exists in `es.yml`, that `es.yml`
defines nothing extra, and that placeholders match. It said nothing about the reverse direction:
keys that **no longer had any reader**. So deleting the last call site of a feature left its
translations behind permanently. 49 had accumulated that way.

### 3. Four `aria-label`s were hardcoded English

`Options navigation`, `Enable Preview`, `Feedback`, and `Typing Timeout` in
`app-sidebar.tsx`, `PreviewSettings.tsx`, `site-header.tsx` and `SnippetsSection.tsx`.

These are not cosmetic. A label with no visible text is read aloud by a screen reader, so for a
blind Spanish user this was an accessibility gap, not a translation nit.

## Solution

- Nav labels resolve through `i18n.t` at render time. `labelKey` is typed as a **literal union**,
  not `string`, because `i18n.t` is typed against the keys WXT generates from `en.yml` — so a
  renamed key becomes a compile error rather than a silently untranslated label. That is what
  would have prevented this in the first place.
- The four `aria-label`s move under a new `options.a11y` block in both locales.
- The gate gains an unused-key check, and it **fails the build**.

  It began as a warning, on the reasoning that a key can legitimately be reserved for
  in-progress work. Review showed that makes it worthless: a warning is a thing people scroll
  past, and — decisively — the _exact_ regression this wave fixed would not be caught. Reverting the
  sidebar to hardcoded English leaves `options.nav.*` translated but unread, and nothing else in
  the suite can see that, because the options components are excluded from unit coverage and the
  e2e keys off `options-nav-*` testids that survive the revert. Verified: with the sidebar
  reverted the gate exits 1, naming exactly those five keys.

  The legitimate case is expressible instead: a key reserved for work in progress goes in a
  `RESERVED` set in the script, so the exemption is explicit and reviewable rather than a blanket
  downgrade.

### What the check deliberately does not report

Each exclusion is a false positive that would otherwise train people to ignore the output:

| Excluded                          | Why                                                                                                                                                    |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| plural arms (`.1`, `.n`)          | the code calls `t(key, [n])` and the runtime picks the arm; the parent key is what must exist                                                          |
| `extName`, `extDescription`       | read by the browser from the generated manifest, not by `i18n.t`                                                                                       |
| any string literal equal to a key | a key reached indirectly through a data table — `labelKey: "options.nav.dashboard"` is alive even though `i18n.t(item.labelKey)` is not a literal call |

It also warns if a non-literal `i18n.t(` call is ever introduced, since that would make its own
result incomplete.

### The rest of the hardcoded English

The sidebar and the four `aria-label`s were the first pass. The remaining 31 findings were
localised in a follow-up, and the durable part is a second check rather than the edits themselves.

`scripts/check-hardcoded-text.mjs` (wired into CI beside the locale gate) reports literal JSX text
and hardcoded `aria-label` / `title` / `placeholder` values, with file:line. Its allowlist is
deliberately tiny — brand names, format tokens, units, and keyboard key names such as
`Ctrl+Shift+Space`, which names keys rather than prose.

**Its limitation is documented in the script and repeated here, because a check that overstates
itself is worse than none:** it only sees text that reaches the DOM as a JSX text node or one of
those three attributes. It cannot see a string produced inside a JSX expression —
`{enabled ? "Enabled" : "Disabled"}` was found by reading, not by the script, and fixed by hand.
Closing that gap means parsing JSX, which is a much larger piece of work than the problem
justifies.

Verified sensitive: restoring one hardcoded label fails the check with its file:line.

## Acceptance Criteria

- [x] The sidebar renders translated labels in every locale.
- [x] A renamed nav key is a compile error, not a silent fallback.
- [x] The four `aria-label`s are localized.
- [x] The gate reports keys that no code reads.
- [x] Plural arms, manifest keys, and indirectly-referenced keys are not reported.
- [x] Every key reported as unused is removed from **both** locales, and the emptied parent
      objects go with them.
- [x] Removing a key that was actually used fails `pnpm compile` — verified, not assumed. The
      generated key union is rebuilt by `wxt prepare`, so this is a real safety net, and it passed
      for all 49 removals.
- [x] `pnpm check:locales`, `pnpm compile`, `pnpm lint`, `pnpm test`, and `pnpm test:e2e` are green.
- [x] A second check, `pnpm check:hardcoded-text`, fails the build on hardcoded user-visible text
      and is wired into CI. Its known limitation is documented in the script, not glossed over.

## Results

en.yml went from **392 keys to 343**, with zero unused keys reported.

The removed keys clustered where the ledger would predict: whole `options.developers.*` subtrees
(`blockedSites`, `versionUpdate`, `typingTimeout`, `topUsage`) left empty by the sections refactor,
plus the old `options.generalSection.*` and `options.feedback.card*` blocks.

## Non-Goals

- **Reviewing the Spanish.** Every string here was written by me. The wiring is verified; the
  translations are not, and a native speaker should read them before release.
- The Spanish for the bulk of the remaining hardcoded English, which is deferred.
